<p align="center">A Zigbee2MQTT-style settings page for <b>ZHA</b> in Home Assistant.</p>

## Why I built this

My home runs on a Home Assistant Green with ZHA, and most of the wall switches are Aqara Z1 and Z1 Pro. The settings I actually wanted (decoupled mode so smart bulbs stay powered, the LED at night, power-on behaviour) are one click away in Zigbee2MQTT, but in ZHA they don't show up at all.

ZHA can talk to them; the device doesn't care which software sends the write. It just doesn't present them. You either dig up cluster and attribute IDs and type them into *Manage Zigbee device* (where ZHA's write service quietly drops attributes it doesn't know about), or you migrate to Zigbee2MQTT, which means re-pairing every device and redoing automations. Neither felt reasonable for flipping a few switch settings.

So this plugin borrows the one thing Zigbee2MQTT has that ZHA lacks, its huge library of device knowledge, and puts it in a settings page for ZHA. The device definitions are generated by running Zigbee2MQTT's own converters, so they stay accurate and keep up as new devices are added, and every setting for a device lives on one page, including the ones ZHA already exposes elsewhere.

## What it does

It adds a **Zigbee Settings** page to the Home Assistant sidebar with:

- **Every setting in one place** for Aqara/Xiaomi, Sonoff, Philips Hue, IKEA and Innr devices: dropdowns, toggles and number fields, with live values read from the device.
- **Raw attributes tab** for any device: read/write any attribute with an explicit data type and manufacturer code.
- Writes go straight through zigpy as typed ZCL frames, then read back so the UI shows what the device actually holds.

## Supported devices

**971 device types, 2288 settings**, generated from [zigbee-herdsman-converters](https://github.com/Koenkk/zigbee-herdsman-converters) (Zigbee2MQTT's device library).

Settings ZHA *also* exposes as entities (start-up behaviour, transition times, thermostat calibration …, 1441 in total) are included too, marked **Also in ZHA**, so you can configure a device completely from one page. Changing one here updates ZHA's entity as well.

| Brand | Device types | Settings | Highlights |
|---|---|---|---|
| Aqara / Xiaomi | 141 | 655 | Wall switches (H1, Z1, Z1 Pro, D1, E1, T1 …) decoupled mode, click mode, LED at night; plugs; FP1/FP1E presence; curtain motors; thermostats incl. external sensor switching |
| Philips Hue | 596 | 1099 | Power-on behaviour and colour, motion sensor LED and sensitivity, wall switch module device mode |
| Sonoff | 42 | 231 | TRVZB/TRV-ZBT valve opening, frost protection, external temperature; SWV water valve duration, amount, fail-safe; SNZB presence and sensors |
| Innr | 114 | 171 | Power-on behaviour and colour temperature |
| IKEA | 78 | 132 | Power-on behaviour; INSPELNING / TRETAKT plug child lock and LED, STARKVIND purifier, VALLHORN motion timer |

Light *controls* (Hue effects and gradients, identify) aren't settings and are left to ZHA's light entities.

Not included: schedules and other text/list values, actions (factory reset, clear history, pairing), and settings whose converter needs a read-modify-write of current device state. `tools/<vendor>.skipped.json` lists every skipped option with the reason.

Some settings are **write-only**: the device expects a proprietary frame and doesn't report the value back. The panel marks these and shows the last value set from it.

## Install

**HACS (recommended):**
1. HACS → ⋮ (top right) → **Custom repositories**
2. Repository: `https://github.com/zernonia/zha-device-settings` — Type: **Integration** → Add
3. Search *ZHA Device Settings* in HACS → **Download** → restart Home Assistant

Updates then appear in **Settings → Updates** like any other HACS integration.

**Manual:** copy `custom_components/zha_device_settings` into `/config/custom_components/` → restart.

Then **Settings → Devices & services → Add integration → ZHA Device Settings**. A *Zigbee Settings* item appears in the sidebar (admin only). On Home Assistant 2026.3+ the integration shows its own icon; older versions show a placeholder.

## How definitions are generated

`tools/generate.js` doesn't re-implement Zigbee2MQTT's converters, it **runs** them: every settable option is fed each possible value through its converter against a mock device that records the resulting ZCL writes (endpoint, cluster, attribute, data type, manufacturer code, value). On top of plain attribute writes it handles:

- **Composite types**: ZCL arrays and structs are pre-serialized and sent verbatim.
- **Numbers inside payloads**: captures at several values locate the changing bytes and fit a linear encoding, so the integration can patch any value into the frame.
- **Device-specific bytes**: each capture runs with a different device address *and* a different frozen clock and random source. Payloads that differ only by the device's IEEE address or the current Unix time get those slots filled at write time; anything else that varies (counters, randomness) is dropped as unsafe to replay.
- **ZHA overlap**: `tools/zha_builtin_attributes.json` (from `export_zha_builtins.py`, which introspects ZHA's entity classes) lists attributes ZHA already exposes; matching settings are tagged `zha_entity` and shown with an *Also in ZHA* chip.

Reads and writes from the panel also update zigpy's attribute cache, so ZHA's own entities stay in sync immediately.

```sh
cd tools && npm install && node generate.js   # writes custom_components/.../definitions/<vendor>.json
```

The *Regenerate definitions* workflow does this monthly against the latest converter and ZHA releases and opens a PR when anything changes. To add a vendor, append its file name (from `zigbee-herdsman-converters/dist/devices/`) to `VENDORS` in `generate.js`. Tuya isn't supported yet: its devices are matched by manufacturer fingerprint and configured through data-point commands rather than attributes.

## Adding your own definitions

Drop a JSON file in `/config/zha_device_settings/`. Entries there override bundled ones for the same zigpy model. Same shape as the generated files:

```jsonc
{
  "id": "my_devices",
  "devices": [
    {
      "models": ["<zigpy model string>"],   // shown under each device in the panel's list
      "model": "VENDOR-MODEL",
      "name": "Brand Device",
      "settings": [
        { "key": "led", "label": "LED at night", "group": "Configuration", "control": "toggle",
          "target": { "endpoint": 1, "cluster": 64704, "attribute": 515, "type": 16, "manufacturer": 4447 },
          "options": [{ "label": "Off", "raw": 0 }, { "label": "On", "raw": 1 }] },
        { "key": "mode", "label": "Mode", "control": "select",
          "target": { "endpoint": 1, "cluster": 64704, "attribute": 4, "type": 33, "manufacturer": 4447 },
          "options": [{ "label": "Quick", "raw": 1 }, { "label": "Anti-flicker", "raw": 4 }] },
        { "key": "threshold", "label": "Threshold", "control": "number", "min": 0, "max": 100, "step": 1, "unit": "%",
          "target": { "endpoint": 1, "cluster": 64704, "attribute": 300, "type": 32, "manufacturer": 4447 },
          "scale": 1, "offset": 0 }
      ]
    }
  ]
}
```

- `type` is the ZCL data type id (16 bool, 32 uint8, 33 uint16, 35 uint32, 48 enum8, 57 float32, 65 octet string …).
- Toggles list `[off, on]` options. Numbers map with `raw = value × scale + offset`.
- Write-only settings use `"target": null` and give each option a `writes` list instead of `raw`.

After editing, restart HA or call the `zha_device_settings/reload_definitions` websocket command.

## Notes for Aqara wall switches

- **Decoupled mode** stops the rocker from switching its relay. ZHA needs to receive the press as an event for automations; check *Logbook* / `zha_event` after switching. If presses don't show up, the device needs a quirk for its multistate input — that's the next piece to add.
- Mains-powered switches answer reads immediately. Sleepy battery devices may not respond until woken.

## Releasing an update

Bump `version` in `custom_components/zha_device_settings/manifest.json` and push to `main`. The *Release* workflow creates a `vX.Y.Z` tag and GitHub release, and HACS offers it as an update. Pushes that don't change the version stay unreleased.

## Development

```
custom_components/zha_device_settings/
  __init__.py        # registers panel, static files, websocket API
  websocket.py       # devices / device_settings / write_setting / raw_read / raw_write / reload_definitions
  zigbee.py          # typed raw ZCL read/write via ZHA's zigpy controller
  definitions.py     # loads definitions, maps raw <-> UI values
  definitions/*.json # bundled definitions (generated)
tools/generate.js    # generates definitions by running Z2M converters against a mock device
  frontend/zha-device-settings-panel.js  # panel (vanilla web component, no build)
```

After editing a definition, call the `zha_device_settings/reload_definitions` websocket command or restart.
